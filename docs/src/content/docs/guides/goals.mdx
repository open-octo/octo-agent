A goal is a standing objective the agent keeps making progress on across idle periods, instead of
stopping once the current message is answered.

```text
/goal Migrate the internal API client from v1 to v2 across all call sites
/goal edit          # adjust the current goal's objective
/goal pause         # stop idle continuation without losing the goal
/goal resume        # pick the continuation loop back up
/goal clear         # drop the current goal
/goal replace       # force-replace a goal that isn't finished (a finished one: just /goal <new objective>)
```

When a session goes idle with an active goal, octo continues working toward it on its own —
the same machinery behind [`/loop`](/docs/guides/loop/), applied to a single durable objective
instead of a recurring prompt. The underlying tools (`get_goal`, `create_goal`, `update_goal`) are
also available to the model directly, so a goal can be created or refined mid-conversation, not
just via the slash command.

:::note[`/goal` is a TUI and Web command]
IM channels have no `/goal` command: they run turns one message at a time, with no idle
continuation loop to pursue a goal between them. A session bound to a chat still carries whatever
goal the model or another transport set — the record lives on the session, not the transport — and
the model can still create or update one through the goal tools mid-conversation.

Between the two surfaces that do have it, only `edit` differs. In the TUI, `/goal edit` with no
text prefills the input box with the current objective for you to revise on the next Enter, and
`/goal edit <text>` is rejected outright — it's prefill-only. In the Web UI, `/goal edit <text>`
edits the objective inline in one step.
:::

## Turning it off

Goals are opt-in per session and can be disabled entirely:

```yaml
# ~/.octo/config.yml
goal:
  enabled: false
```

With goals disabled, `/goal` reports itself as unavailable rather than silently no-op-ing.
