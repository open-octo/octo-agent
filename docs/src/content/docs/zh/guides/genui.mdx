让 agent 做个对比，通常拿到的是一张 markdown 表格；让它汇报状态，拿到的是三段文字。GenUI 让它改用
**面板**回答：一小棵真实组件树——指标卡、可筛选的表格、图表、mermaid 流程图、表单——直接渲染在对话里。

真正值得理解的是渲染**之后**发生的事。切个 tab、筛一下表格、拖一下滑块、答一道选择题——这些都不是
"对话行为"，所以它们不会走到模型：全在你的浏览器里当场完成，零延迟、零 token。只有面板自己确实答不
上来的时候，模型才会介入。

## 面板有两种到达方式

Agent 选哪一种，决定了这个面板能做什么、以及在哪儿能看到。

| | `render_ui` 工具 | 内联 ` ```octo-ui ` fence |
|---|---|---|
| 渲染形态 | 一张工具结果卡片 | 和回复正文混排的实时组件树 |
| 交互节点 | 不支持——只有只读组件 | 支持 |
| Web UI | ✅ | ✅ |
| TUI / IM | 压根不显示工具卡片 | 被替换成一行占位文字 |

工具这条路在所有端都能安全降级，所以 agent 被教成：只要不确定你是不是在 Web UI 上，就优先用工具
＋一段能独立读懂的纯文本回复。交互面板是 Web UI 独有的能力——终端和聊天软件里没有办法渲染组件树。

## 面板里能放什么

只读节点，两条路都支持：

- **文字与布局** —— 段落、行列容器、卡片、分隔线、可折叠区块
- **数据** —— 表格、无序列表、键值对定义列表
- **指标** —— 带涨跌 delta 的指标卡、徽章、进度条
- **强调** —— info / success / warning / danger 四种语气的提示框
- **代码与图** —— 带语法高亮的代码片段，以及内联渲染的 mermaid 图
- **图表** —— 柱状、折线、面积、饼图，可堆叠，可带坐标轴标签和图例

交互节点，仅内联 fence 支持：

- **控件** —— 文本框、数字框、滑块、多行文本、下拉、单选、复选、开关
- **结构** —— 标签页
- **动作** —— 按钮
- **测验** —— 带解析的单选题，选完立即判分

配色是自动分配的，跟随你的主题。spec 里**没有**任何颜色或 CSS 字段，也没有 3D / WebGL 节点——面板
是结构化数据，不是一个样式画布。

## 本地交互

有三个机制让面板能自己回答问题，这也是大多数面板压根不花一个 turn 的原因：

- **条件区块** —— 任何节点都能声明一个针对某字段值的条件，只在条件成立时出现；支持相等、集合包含、
  数值区间。"高级选项"随开关出现，是一个条件，不是一次往返。
- **表格筛选** —— 表格可以被一个文本框按它自己的某一列做大小写无关的筛选，筛的是已经加载进来的行。
- **表格排序** —— 表头可点击，循环 未排序 → 升序 → 降序。整列都是数字时按数值排，否则按字典序。

Agent 被教过：没人读的输入框就是个什么都不干的控件——所以一个滑块必须被某个条件或某个筛选用上。

面板确实需要模型的时候——要拉它手上没有的数据，或者要做一件真实世界的事——那才是**按钮**。按下去
会连同面板里**所有**字段的当前快照一起发出去，所以 agent 看到的是整张表单，不只是那个按钮。

## 可寻址面板与静默轮

面板可以带一个 `id`。就这一个字段，会彻底改变"按下按钮"的手感。

不带 id 时，面板是一次性的：动作作为一条可见的用户消息发出，agent 的回答作为一条可见的回复，新面板
长在旧面板下面。对于一份没人会再动的总结，这是对的。

带 id 时，这次往返是一个**静默轮**：动作和回复都不会画进对话，回复直接**就地替换那个面板**，位置不
变。带刷新按钮的仪表盘会自己更新，而不是每按一次就在对话里多出一对气泡。

有两个后续影响值得知道：

- **要就地更新，agent 的回复必须只有那个面板、别的什么都没有。** 如果它需要解释、拒绝或者反问，它会
  正常说话——那这条回复就是一条普通的可见消息。这是设计好的降级路径，不是失败。
- **静默轮隐藏的是渲染，从不隐藏历史。** 那两条消息在会话文件里、在导出里都是普通消息，而且对话里
  会在被隐藏的那一对的位置留一个标记。面板不可能在记录上无痕地变化。

## 状态能扛过刷新

你在面板里填的内容、开着的是哪个 tab、展开了哪些区块——全都绑在面板的 id 上，回来时会恢复。

- **按浏览器、按设备。** 面板状态是"某个人在某块屏幕前"的属性，所以它存在 `localStorage` 而不是会话
  文件里。手机和桌面看同一个会话，各自保留独立状态，永不同步。
- **面板自己刷新也扛得住。** Agent 发来新版本时，字段还存在的值会保留，不存在的丢掉——所以一个仪表盘
  刷新之后，仍然停在你设的那个筛选条件下。
- **只存你填进去的东西。** 没有凭证、没有 token；纯文本框是唯一的自由文本控件，而且刻意没有密码
  类型的输入框。

## 模型能看到什么、看不到什么

本地交互对 agent 是刻意不可见的。如果你筛完表格接着问"这个为什么这么低？"，你问的是一个它看不到的
视图——先按面板上的提交按钮，或者把你筛了什么直接说出来。

这是一个有意的取舍：把面板状态挂到每一条外发消息上，会为了一个"显式按钮已经覆盖"的场景，去撑大每个
会话里的每一条消息。

## 上限

Spec 是有上限的，而且超了是**静默截断**，不是报错：

| | 上限 |
|---|---|
| 单个面板节点总数 | 200 |
| 树深度 | 8 |
| 表格行 / 列 | 500 / 50 |
| 列表或键值对条目 | 200 |
| 下拉、单选或测验选项 | 50 |
| 标签页 | 8 |
| 图表 series / 每个 series 的点 | 8 / 100 |
| 文本字段长度 | 500 字符 |
| 表格单元格 | 2000 字符 |
| 代码、图或多行文本内容 | 5000 字符 |

无法识别的节点类型只会丢掉它自己和它的子树，兄弟节点照常渲染。链接只接受 `http`、`https`、`mailto`
和 `tel`，其它一律丢掉整个节点——一个点不开的链接看起来仍然像个链接。

正因为截断是静默的，agent 被明确告知：不要把一份报告体量的文档或者一个大数据集塞进面板。内容装不进
一条正常回复，这本身就是"它该去 artifact"的信号。

## 面板、artifact 还是轻应用？

三者都能让 agent 产出非纯文本的东西，而把内容送错通道，结果是"不报错但明显不对"。

| 用 | 什么时候 |
|---|---|
| **面板**（GenUI） | 这一条回复里的一次性结构，你现在可能会动它——一次对比、一份状态汇总、一个小表单。没有理由存成文件。 |
| **Artifact** | 该活得比这条回复更久的交付物——文档、独立页面、本身就是产出的图表，以及任何需要真正图表库或者热力图/桑基图/地图的东西。用 `write_file` 写、用 [`show_artifact`](/docs/zh/reference/tools/) 展示。 |
| **[轻应用](/docs/zh/guides/light-apps/)** | 你以后还会再打开的工具，存下来之后从 Web UI 零 token 启动。 |

同一条线也区分 `mermaid` 节点和图表 artifact：解释 agent 刚说的那句话的图，属于面板；本身就是交付物
的可视化，属于 artifact。

## 如果你更想要纯文字

模型关于面板的全部知识都来自内置的 `genui` skill。把它禁掉，模型就不再被教这些节点类型，实际效果就是
它回到用 markdown 回答：

```yaml
# ~/.octo/config.yml
tools:
  disabled_skills: [genui]
```

这是一个"不再教它"的开关，不是硬关断。`render_ui` 工具仍然在工具列表里，渲染器也仍然会解析
` ```octo-ui ` fence——所以一个照样产出 fence 的模型仍然会得到面板；而已经在对话里的面板，无论如何都
继续渲染。

Mermaid 是按需加载的，只在一个会话真的渲染第一张图时才拉——从不出图的会话压根不会下载和解析它。
