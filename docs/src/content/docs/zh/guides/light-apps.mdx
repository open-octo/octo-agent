当你让 Agent 生成一个 HTML 页面——比如数据对账工具、格式转换器、日报模板——如果这个任务是**可重复**的，
Agent 会主动提醒你把它保存为一个**轻应用**。保存后，你可以随时在 Web 界面里打开使用，不需要再消耗 LLM token。

## 它是什么

轻应用是 Agent 用纯前端技术（HTML + CSS + JS）写的页面，存储在本机 `~/.octo/light-apps/`
目录下：

```
~/.octo/light-apps/<slug>/
├── manifest.json   # 元数据：名称、描述、图标、创建时间
├── index.html      # 页面本体
└── …               # 可选：页面用相对路径引用的脚本、样式、图片、字体、模型、音视频
```

每个轻应用运行在自己的独立源（`<slug>.apps.localhost`）上，行为和普通网页一致：`localStorage`
跨访问持久、下载和全屏可用、同目录文件用相对路径直接加载。它碰不到 octo 自己的 API，也不需要后端。
轻应用只能在运行 octo 的本机浏览器中打开，手机端（tunnel）不提供。

## 适用场景

✅ **适合做成轻应用的任务**：
- 重复性工具：数据对账、格式转换、CSV 合并
- 模板生成器：日报模板、周报模板、清单生成
- 输入→输出逻辑固定的任务：校验器、计算器、格式化工具
- 需要离线可用的工具

❌ **不适合做成轻应用**：
- 一次性的分析或调研
- 必须依赖 LLM 推理的任务
- 需要后端 API / 数据库的工作流（用 [Skills](/docs/zh/guides/use-skills/) 或 [Workflows](/docs/zh/guides/workflows/) 代替）

## 如何创建

Agent 会自动判断一个 HTML 页面是否适合保存为轻应用。流程如下：

1. 你在对话中让 Agent 生成一个 HTML 工具页面
2. Agent 生成并预览后，如果判断任务可重复，会主动问：「保存为轻应用？以后随时在轻应用面板打开，不消耗 token。」
3. 你确认后，Agent 用 `write_file` 直接把文件写入 `~/.octo/light-apps/<slug>/`
4. slug 由小写字母、数字和连字符组成，从应用名称自动推导

你也**不需要手动操作文件系统**——Agent 会自动完成一切。

## 管理与使用

在 Web 界面的导航栏点击「轻应用」，你会看到一个卡片网格，列出所有已保存的轻应用：

- **打开**：在侧边栏的 Artifacts 面板中以 preview 模式渲染，可以直接交互使用
- **编辑**：跳转到 Agent 对话，告诉 Agent 当前内容和修改需求，让它帮你更新
- **删除**：确认后删除该轻应用

Agent 生成的 HTML artifact 也可以在 Artifacts 面板中一键「保存到轻应用」。

## 挂进界面

轻应用默认住在「轻应用」页面，从 Artifacts 面板里打开。如果你做了一个天天都要用的——
画板、计算器、看板——给它的 `manifest.json` 加一个 `mount` 字段，它就能在界面里有个固定位置。

```json
{
  "slug": "sketch",
  "name": "画板",
  "description": "随手画图的画布",
  "icon": "🎨",
  "mount": "view"
}
```

| `mount` | 出现在哪 |
| --- | --- |
| *不写* | 只在「轻应用」页面出现——默认行为，也是所有现有应用的行为。 |
| `"view"` | 左侧导航多一项，点进去整页渲染。 |
| `"panel"` | 右侧面板多一个槽位，和会话制品、diff 审阅并列。 |

这个字段要你自己手写：Agent 不会主动加。一个应用值不值得在你的界面里占个固定位置，
这是你的判断，不是它的。

挂载的应用同样受轻应用的本机限制约束——它们从 `<slug>.apps.localhost` 渲染，
而这个域名只在跑 `octo serve` 的那台机器上能解析。当你从别的设备打开 Web UI 时，
挂载入口会被隐藏，而不是显示一个点不开的入口。「轻应用」页面本身的行为不变。

### 一个完整的例子

一个占一整页的画板。两个文件，不需要构建：

```json
// ~/.octo/light-apps/sketch/manifest.json
{
  "slug": "sketch",
  "name": "画板",
  "description": "随手画图的画布",
  "icon": "🎨",
  "created_at": "2026-09-20T00:00:00Z",
  "mount": "view"
}
```

```html
<!-- ~/.octo/light-apps/sketch/index.html -->
<!doctype html>
<meta charset="utf-8">
<meta name="viewport" content="width=device-width, initial-scale=1">
<style>
  :root { color-scheme: light; --bg: #fff; --fg: #1d1d1f; --line: #0001; }
  :root[data-theme="dark"] { color-scheme: dark; --bg: #16181c; --fg: #e8e8ea; --line: #fff2; }
  body { margin: 0; height: 100vh; display: flex; flex-direction: column;
         background: var(--bg); color: var(--fg); font: 13px system-ui, sans-serif; }
  .bar { display: flex; gap: 10px; align-items: center; padding: 8px 12px;
         border-bottom: 1px solid var(--line); }
  canvas { flex: 1; touch-action: none; cursor: crosshair; }
  button { font: inherit; color: inherit; background: none; cursor: pointer;
           border: 1px solid var(--line); border-radius: 6px; padding: 3px 10px; }
</style>

<div class="bar">
  <input id="colour" type="color" value="#0e7490">
  <input id="size" type="range" min="1" max="24" value="3">
  <button id="clear">Clear</button>
  <button id="save">Save PNG</button>
</div>
<canvas id="c"></canvas>

<script>
  // The host passes the resolved theme on the URL, so the app can match the UI.
  const theme = new URLSearchParams(location.search).get('theme')
  if (theme === 'dark') document.documentElement.dataset.theme = 'dark'

  const c = document.getElementById('c')
  const ctx = c.getContext('2d')
  let drawing = false

  // Resizing clears the bitmap, so the strokes are re-drawn from the copy the
  // canvas held before the resize.
  function fit() {
    const snap = document.createElement('canvas')
    snap.width = c.width; snap.height = c.height
    if (c.width) snap.getContext('2d').drawImage(c, 0, 0)
    c.width = c.clientWidth * devicePixelRatio
    c.height = c.clientHeight * devicePixelRatio
    ctx.scale(devicePixelRatio, devicePixelRatio)
    ctx.lineCap = ctx.lineJoin = 'round'
    if (snap.width) ctx.drawImage(snap, 0, 0, snap.width / devicePixelRatio, snap.height / devicePixelRatio)
  }
  addEventListener('resize', fit)
  fit()

  c.addEventListener('pointerdown', e => {
    drawing = true
    c.setPointerCapture(e.pointerId)
    ctx.beginPath()
    ctx.moveTo(e.offsetX, e.offsetY)
  })
  c.addEventListener('pointermove', e => {
    if (!drawing) return
    ctx.strokeStyle = document.getElementById('colour').value
    ctx.lineWidth = document.getElementById('size').value
    ctx.lineTo(e.offsetX, e.offsetY)
    ctx.stroke()
  })
  c.addEventListener('pointerup', () => {
    if (drawing) { drawing = false; strokes++; publish() }
  })

  // ── Let the agent see this canvas ────────────────────────────────────────
  //
  // octo mirrors whatever an app publishes; the model reads it through the
  // lightapp_state / view_lightapp tools. One way: publishing describes the app
  // to the model, it grants the app no access to the conversation.
  let strokes = 0
  let publishTimer = 0
  function publish() {
    clearTimeout(publishTimer)
    publishTimer = setTimeout(() => {
      window.octo?.pushState({
        digest: strokes
          ? `A hand-drawn sketch, ${strokes} stroke(s).`
          : 'An empty sketch canvas — nothing drawn yet.',
        summary: { strokes },
        image: c,            // a canvas is accepted directly
      })
    }, 400)
  }
  publish()

  // ── Take what the agent sends ────────────────────────────────────────────
  //
  // The agent can hand this canvas an image (ask it to generate something from
  // your sketch). Draw it in, then publish again so the agent can see the
  // result of what it just sent.
  window.octo?.onDelivery(({ blob, note }) => {
    const img = new Image()
    img.onload = () => {
      // Fit inside the canvas, centred, without distorting the image.
      const scale = Math.min(c.clientWidth / img.width, c.clientHeight / img.height, 1)
      const w = img.width * scale
      const h = img.height * scale
      ctx.drawImage(img, (c.clientWidth - w) / 2, (c.clientHeight - h) / 2, w, h)
      URL.revokeObjectURL(img.src)
      strokes++
      publish()
      if (note) console.log('[octo]', note)
    }
    img.src = URL.createObjectURL(blob)
  })

  document.getElementById('clear').onclick = () => {
    ctx.clearRect(0, 0, c.width, c.height)
    strokes = 0
    publish()
  }

  // The plain <a download> idiom: the host turns it into a browser download or
  // the OS save dialog in the desktop app.
  document.getElementById('save').onclick = () => {
    const a = document.createElement('a')
    a.download = 'sketch.png'
    a.href = c.toDataURL('image/png')
    a.click()
  }
</script>
```

刷新 Web UI，**画板**就出现在左侧导航里，图标就是 manifest 里那个 emoji。
把 `mount` 改成 `"panel"`，它就转到右侧面板的切换器里，和会话制品、diff 审阅并列。

那个 `window.octo.pushState` 调用就是让 agent 能看见你画的东西的关键：
画完问它「我刚画的是什么」，它会先读 digest，再去看图。见下面的
[让 agent 看见里面](#让-agent-看见里面)。

## 让 agent 看见里面

轻应用是封闭的：它跑在自己的 origin 上，外面罩着一层把所有网络出口都关死的策略。
所以默认情况下 agent 根本不知道它开着，更不知道里面有什么。

应用可以主动发布一份自己的快照：

```js
window.octo.pushState({
  digest: '一张手绘草图，3 笔。',        // 一句话，写给模型看的
  summary: { strokes: 3 },              // 可选的结构化信息
  image: canvasOrBlob,                  // 可选的截图
})
```

agent 这边有两个工具：`lightapp_state` 读取每个打开的应用的 digest（很便宜，
所以你一提「我画的那个」它就能去看一眼），`view_lightapp` 把截图作为一张真正的
图片拉进对话里，它就能直接看着图说话。

**发布不会给你的应用任何东西**——拿不到对话、拿不到接口、拿不到凭据。
状态一变就可以调，octo 会合并连续的推送，所以画布每一笔都推也没问题。

### 接收 agent 送过来的东西

agent 可以往你的应用里递一个文件——让它照着你的草图生成一张图，
它可以直接把结果放到画布上。注册一个处理函数来接收：

```js
window.octo.onDelivery(({ blob, name, note }) => {
  // 画进去、显示出来，或者干脆不理 —— 这是你的应用
})
```

这是唯一的入站方向，而且只带一个文件和一句备注，别的什么都没有：
没有对话内容，也没有要执行的指令。不注册处理函数的应用就永远收不到东西，
而 agent 会像了解你的应用的其他一切一样知道结果——读你接下来发布的状态。

快照只存在内存里，octo 停掉或应用关闭后就没了。

## 技术约束

Agent 在生成轻应用时遵守以下规则：

- 页面需要的文件放在应用目录里，用相对路径引用；外部脚本和样式只允许来自知名 CDN（cdnjs、jsdelivr、unpkg、Google Fonts 及其国内镜像），其余会在渲染时被剥离
- 页面的网络访问只限于自己的文件和这些 CDN：不能调用其他 API、不能加载其他站点的图片、不能访问 octo 的 API
- 文件处理用 `FileReader` + `<input type="file">`
- 导出文件（生成的图片、转换后的文件等）用标准的 `<a download>` 写法，宿主负责落盘：浏览器里走正常下载，桌面端弹出系统保存对话框
- 图标用 emoji 或内联 SVG
- 遵循 `artifact-design` skill 的布局与配色规范

这些约束 Agent 都清楚——你只需要告诉它要做什么，它会自动处理技术细节。
