Web UI 出厂时只有一套配色、一屏开场、一组固定的面板。其中三样是你的，改它们的方式是写一个
文件——不用 fork octo，不用重新编译，也不用去读它的组件树。

| 你想改的 | 用 | 放在 |
| --- | --- | --- |
| 颜色、壁纸、字体、圆角 | [主题](/docs/zh/guides/themes/) | `~/.octo/themes/<id>/` |
| 新会话那一屏的卡片、标题，以及它们上方那块空间 | [起始页](/docs/zh/guides/start-screen/) | `~/.octo/landing/config.json` |
| 左侧导航里的一页，或者右侧面板里的一个标签 | [挂进界面的轻应用](/docs/zh/guides/light-apps/#挂进界面) | `~/.octo/light-apps/<slug>/manifest.json` |

## 这三样的共同点

**它们是文件，不是代码。** 不需要构建、不需要 npm install、不需要重新编译二进制。写好文件，
刷新页面。

**不一定要你自己写。** 这三种格式 agent 都认识——「给我做一套墨绿色的主题」「把画板放到侧边栏」
「把起始页换成我实际在做的事」，它直接就能做，然后你在它写出来的文件上改。

**octo 自带的那些用的是同一套格式。** Ocean、Blossom、Vogue 三套主题是 octo 第一次运行时
写进 `~/.octo/themes/` 的，后面所有环节都分不出它们和你写的有什么区别。抄一套改，是最快的起步方式。

**删掉文件就回到默认。** 没有 `landing/config.json` 就是内置的那一屏；`manifest.json` 里
没有 `mount`，应用就和其他应用一样待在轻应用页。唯一不对称的是 octo 给你铺的主题：删了就是删了，
不会再铺回来——每次升级都把你的决定撤销一遍，那才是不对的。

**它们互不干涉。** 主题决定起始页长什么样，起始页的配置决定它说什么。两边谁都不知道对方存在。

## 做不到的事，以及为什么

**没有组件 API。** 你不能用自己的组件替换界面的某一块，不能在应用自己的页面里跑 JavaScript，
也不能从你写的面板里调 octo 的接口。挂进来的轻应用跑在它自己的 origin 上，外面罩着一层把所有
网络出口都关死的策略——它是 octo 托管的一个网页，不是加载进 octo 的插件。

这条线是故意划的，也正是上面那三样敢让你放心用的原因。伸手进界面内部的定制，会在界面第一次
变动时就坏掉，而界面每个版本都在变；能调接口的扩展，则等于凭一个你从别处抄来的目录，就握住了
你的整个会话——每一把 key，每一段对话。数据能扛过升级，依赖我们内部结构的代码不能。

同一条道理还带来一个动手前值得知道的限制：凡是要渲染轻应用的地方——挂载的页面、挂载的面板、
起始页上嵌入的 hero 应用——只在浏览器和 `octo serve` 同机时出现。用手机打开 Web UI 时，
这些入口是被隐藏，而不是显示成一个打不开的框。

## 从这里开始

- **[制作主题](/docs/zh/guides/themes/)**——完整的变量表、那条谁都会踩的「两个块」规则，
  还有一份可以直接抄的最小主题。
- **[改起始页](/docs/zh/guides/start-screen/)**——用你自己的话写开场卡片，在上方放一张图或
  一段动画，把常用轻应用 pin 成快捷入口。
- **[轻应用](/docs/zh/guides/light-apps/)**——它是什么、agent 怎么帮你做；
  [挂进界面](/docs/zh/guides/light-apps/#挂进界面) 是给它一个固定位置的那一个字段。
