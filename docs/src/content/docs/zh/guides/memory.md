---
title: 让它拥有记忆
description: 以纯 markdown 文件形式保存在本地的跨会话记忆。
---

octo 会跨会话记住你的偏好、项目约定和过去的纠正——存在本地的 `~/.octo/memories/<project-slug>/`
下面，绝不上云。

## 工作原理

没有专门的 `remember`/`forget` 工具，也没有代码驱动的整理步骤。agent 管理记忆的方式和管理任何文件
一样——用 `read_file` / `write_file` / `edit_file`——只是遵循一个约定：

- `MEMORY.md` —— 索引。每次会话都会被注入系统提示（最多前 200 行 / 25KB，以先到者为准——
  和 Claude Code 自己的注入上限一致）。
- `<topic>.md` —— agent 按需创建和读取的详情文件，从索引里链接过去。

整棵 `~/.octo/memories` 目录树在[权限引擎](/docs/zh/reference/permissions/)里自动带了一条
`write_file`/`edit_file` 的 `allow` 规则，所以 agent 管理笔记时每次写入都不会弹确认——包括你让它
改另一个项目时，把事实归档进**那个**项目的记忆里。这棵树以外的地方还是照常受门控；
`--no-memory` 会连同注入一起收回这条规则。

```bash
octo memory list           # 列出项目自己的和继承来的记忆文件
octo memory path           # 打印项目的和继承的记忆目录
octo memory path <dir>     # 打印另一个目录的（agent 就是这样解析别的项目的记忆目录）
octo --no-memory           # 单次会话关闭记忆注入
```

## 作用域

记忆按**项目**划分作用域，而什么算项目由你说了算，不由 git 说了算。很多真实工作发生在 git
完全不知道的目录里，也有很多仓库你只是路过、并没有在上面干活。

项目从哪里来，取决于你怎么跑 octo：

- **Web / 桌面 / IM** —— 来自会话归属的项目（侧栏「项目」区里的那些条目，每个项目就是一个工作目录）。
  同一个项目下的每个会话都读写这个项目的笔记。不归属任何项目的散落任务用下面那份共享记忆，
  这正是重点：这类会话往往是在改别处的代码（"帮我修 X 项目的登录 bug"），
  埋进一个别人不会打开的目录里的笔记，后来真正在 X 项目里干活的会话读不到。
- **CLI / TUI** —— 你当前所在的目录**就是**项目；你 `cd` 过去就是为了在它上面干活。
  用 `-c` 恢复的会话如果在 Web 里已经归入某个项目，那它拿到的是那个项目的记忆，
  跟你从哪儿启动 octo 无关。

这两条规则对同一个目录可能给出不同答案，值得知道是什么时候。你在 CLI 里干活的那个仓库，
在 CLI 下有自己的记忆；但一个只是**把工作目录指向**那里的 web 会话是任务，读的是共享那份。
把它设成项目（侧栏「项目」区）两端就一致了。`octo memory list` 发现这种情况时会明说：
如果没有任何项目指向你当前所在的目录，它会告诉你这些笔记只有 CLI 会话读得到。

还有一份主目录级别的索引（`~/.octo/memories/<home-slug>/MEMORY.md`）会被继承进**每一个**项目，
在项目自己的索引**之前**注入——适合放不属于某个具体项目的东西，比如你喜欢的工作方式；
具体到某个项目的事实应该放进那个项目自己的记忆里。在主目录里跑不需要任何特例：
主目录自己的那个目录**就是**这份共享记忆。

## 除了普通笔记，还有两种规则区块

`MEMORY.md` 支持两个可选的区块，行为跟普通的索引条目不一样：

- **必须遵守的规则**——和 `MEMORY.md` 的其他内容一样在系统提示里；对话积累到离它很远（大约 10 万个 token）时再提醒一次，让它始终离当前的对话不远；如果会话的系统提示是在这条规则加进来之前冻结的，会立刻提醒。适合那种绝对不能漏掉的事。
- **触发式规则**——每条规则配一组触发关键词；一个会话里，只有你输入的内容第一次命中某个
  关键词时才会被提醒一次（英文关键词按单词边界匹配，所以 `deploy` 不会被 `deployment` 误触发；
  中文关键词按子串匹配）。

这两种都是作为附加在你这条消息上的提醒发出去的，而不是编辑进系统提示本身，所以被缓存的
prompt 前缀不会变。一份两种区块都没有的普通索引，除了索引本身不会有额外开销。

## 保存提醒

一次 `terminal` 调用，如果命令匹配 `gh pr create` 或 `gh pr merge` 并且执行成功，octo 会在那次
工具结果后面追加一条一次性提醒，建议模型想一想刚落地的这次工作里有没有什么值得记下来的东西——
一个已经定下来的决定、一个被否掉的方案、一条以后的会话必须遵守的约束。这个提醒每个用户轮次最多
触发一次，所以连续跑一串 git 命令不会被反复打扰；用
[`octo hooks list`](/docs/zh/guides/hooks/) 能看到它和其他配置的 hook 列在一起。

## 记忆的改动什么时候生效

所有入口（CLI、Web、IM）都只在会话第一次对话时组装一次系统提示，之后整个会话一直用这份原文：
以后恢复这个会话、或者把一个 IM 聊天重新绑定到它，拿到的都是同一份冻结的提示，不会重新组装。
这是故意这么设计的，不是疏漏：如果每一轮都重新组装，会话中途可能变化的任何东西（包括记忆文件）
都会让提示的文本变掉，这一轮以及之后每一轮的提示缓存就都失效了。

所以你在会话中途告诉 agent 的事，本来就已经在这次对话自己的历史里了，agent 不需要重新读一遍
`MEMORY.md` 才知道。agent 在会话里**写进**记忆的内容，从**下一个**会话开始生效（不管用哪个入口），
而这正是一份纯索引文件该起作用的时候：服务一个没有经历过"这件事是怎么学到的"那段对话的新会话。

## 一般会记住什么

实际使用中，agent 会用它来记录代码本身恢复不出来的信息：谁在做什么、为什么这么做，你明确表达过的
稳定偏好（"这个仓库一律用 worktree"），以及你纠正过不止一次的地方。它不会重复 `git log`
或代码里已经写明的内容。

:::tip
如果 `MEMORY.md` 超出了注入预算，octo 会追加一条截断警告，而不是悄悄丢掉内容——这是该把详情
整理进 topic 文件的信号了。
:::
