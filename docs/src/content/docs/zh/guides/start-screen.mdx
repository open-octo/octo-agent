新建会话时看到的那一屏给了四个入口：看懂一个项目、做个功能或小工具、查资料做调研、写点东西。
四张里有两张是冲着代码去的，而 octo 不只是拿来写代码的——用它的人比我们更清楚自己的四件事
是什么。做法务的那四张，和做内容的那四张，不会是同一批。

`~/.octo/landing/` 可以把它们整个换掉：

```
~/.octo/landing/
├── config.json
└── hero.webp        （可选——config.json 指到的任何图片）
```

```json
{
  "title": "今天动哪块？",
  "subtitle": "挑一个，或者直接开始输入。",
  "hero": { "image": "hero.webp", "height": 200 },
  "cards": [
    {
      "icon": "🔍",
      "title": "拆解一条笔记",
      "prompt": "帮我拆解这条笔记：钩子、结构、为什么能火。"
    },
    {
      "icon": "ant-design:file-text-outlined",
      "title": "审一份合同",
      "prompt": "帮我看这份合同，告诉我哪些地方需要注意。"
    }
  ],
  "apps": ["sketch"]
}
```

刷新 Web UI 就能看到。删掉这个目录，内置那一屏就回来了。

| 字段 | 说明 |
| --- | --- |
| `title` | 大标题。不写就用内置的（内置的有中英翻译）。 |
| `subtitle` | 标题下面那行。同上。 |
| `cards` | 整个替换四张卡。最多 8 张；列数跟着数量走，超过四张会换行。 |
| `cards[].title` | 卡片上的标题。必填。 |
| `cards[].prompt` | 点它之后填进输入框的内容。必填。 |
| `cards[].icon` | 一个 emoji，或者图标名（如 `ant-design:tool-outlined`）——不含 `:` 的一律当文字画。可选，**建议用 emoji**，原因见下。 |
| `hero` | 填章鱼标记上方那块空白。见下。 |
| `apps` | 轻应用的 slug，以快捷入口的形式显示在卡片下方。最多 8 个。没装的 slug 会被跳过。 |

### 关于图标

**emoji 一定能用。** 不含 `:` 的一律当文字画，所以 `🔍`、`⚖️`、甚至一个字母都能显示。

含 `:` 的当图标画——但 octo 的图标是离线打包的，从不请求 Iconify 的接口，
所以只有 octo 自己用到的那些图标才存在。写一个它没带的名字，结果是一块空白，
而且没有任何地方会告诉你原因。除非你抄的是 octo 界面里已经见过的名字，否则用 emoji。

## hero 区

章鱼上方是这一屏最空的地方。`hero` 用来填它，来源二选一——**只能选一个**：

```json
"hero": { "image": "hero.webp", "height": 200 }
```

一张放在 `config.json` 旁边的图片。**GIF 和 WebP 动图都能用**，「放个动画」通常指的就是这个。
可用类型：`.webp`、`.png`、`.jpg`、`.jpeg`、`.gif`、`.avif`——SVG 被刻意排除，
因为它能携带脚本，而这些文件是从应用自己的 origin 提供的。

```json
"hero": { "app": "sketch", "height": 240 }
```

嵌一个[轻应用](/docs/zh/guides/light-apps/)——一个时钟、一块看板，或者一个还没开始对话就能
先画两笔的画板。轻应用那一整套机制原样适用，包括状态发布，所以 agent 能看见里面有什么。

`height` 单位是像素，会被限制在 80–420 之间：这块区域要和卡片、输入框分这一屏。

**只能嵌一个。** 嵌好几个的着陆页就是仪表盘了，而每一个 frame 都是你的第一屏要等的东西。
`image` 和 `app` 同时给时 image 生效——一个页面自己悄悄跑起一个应用，是两者里更糟的那种意外。

嵌入的应用只在浏览器和服务器同机时出现，和挂载的轻应用同一条规则。从网络上访问时
你看到的是没有 hero 的那一屏，而不是一个打不开的框。

## 点一下卡片会发生什么

它**只是把 prompt 填进输入框，不发送**。这是有意的：下面的工作目录和模型选择器仍然有效，
你还可以先改几个字再发。入口是个起点，不是绕过这些控件的快捷方式。

所以一段好的 prompt 读起来应该像你本来就会打的第一句话——包括那些你反正都要补充的部分
（「先问我读者是谁」「动手之前先跟我对一遍思路」）。

## 内置的四张

想在默认四张的基础上改，得先知道它们写的是什么。内置卡片不在任何你能打开的文件里，
而是随 octo 的 i18n 走，所以列在这里：

| 标题 | 提示语 |
| --- | --- |
| 看懂一个项目 | 帮我看懂这个项目：它是做什么的、代码是怎么组织的、我该从哪里开始读。 |
| 做个功能或小工具 | 我想做一个小工具，先跟我对一遍需求和实现思路，再动手写。 |
| 查资料做调研 | 帮我查一个主题的资料，整理成一份简报，写清楚关键结论和信息来源。 |
| 写点东西或整理 | 帮我写一份文档，先问清楚读者是谁、要多长、重点讲什么，再开始写。 |

要改哪张，把哪一行抄进自己的 `cards` 里再改——你的卡片按你写的原文显示。另外，
如果你只想加 hero 或轻应用快捷方式，`cards` 整个不写就行：内置四张会保留。

## 几条值得知道的规则

- **是替换，不是合并。** 你的四张不等于内置四张加上你的。替一半的结果谁都不认。
- **你写什么就显示什么。** 内置卡片走 octo 的 i18n 有中英两版；你写的是你的，
  用什么语言写就用什么语言显示。
- **配置写坏了，丢的是定制而不是这一屏。** JSON 格式错、某张卡没写 prompt、标题写了 400 字——
  各自被丢弃或截断，最后你落在内置那一屏，而不是一个报错页。这是个你手改的文件，
  写漏一个逗号是常态而不是意外。

## 顺带一提

这里改的是**内容**。同一屏的**外观**——背景、强调色、字体——由主题决定，两者是叠加的：
见[制作主题](/docs/zh/guides/themes/)。
