Agent 写出来的、能渲染的东西——HTML 页面、Markdown 文档、图片——都会在 Web UI 右侧的
**制品**面板里打开，就在产出它的那段对话旁边。用 `write_file` / `edit_file` 写的文件会自动出现；
别的想给你看的东西，agent 会用 [`show_artifact`](/docs/zh/reference/tools/) 送过来。

HTML 和 Markdown 制品在面板里有**预览** / **代码**两个视图，展开按钮把预览铺满全屏，图片直接渲染。
面板左上角的切换器在本次会话的制品和工作区 diff 之间切。

## 一个 HTML 制品是怎么跑的

每个制品都从自己的源 `<token>.artifacts.localhost` 提供，所以它就是一个普通网页：脚本能跑、
向白名单 CDN 发 `fetch` 能通、全屏能用。octo 自己的 API 在那个源上不存在，而且页面外面罩着一层
把网络出口关死的策略——agent 写出来的页面读不到你的对话、你的文件，也够不着 octo 能够着的任何东西。

这层封闭也正是 agent 读不回页面的原因。HTML 是它写的，但它并不知道这份 HTML **渲染出来是什么样**
——布局有没有崩、图表有没有画出来、对比度够不够。

## 让 agent 看见

页面靠发布一份自己的快照来补上这个缺口。一个调用，没有别的准备工作：

```js
window.octo?.pushState({
  digest: '一张 Q3 销售柱状图，8 根柱子，9 月最高。',
  summary: { bars: 8, peak: 'September' },   // 可选，任意 JSON
  image: canvasOrBlob,                        // 可选截图
})
```

- **`digest`** 是契约：一句话，写给一个看不见屏幕的读者。你指着页面说「这个图」「我选中的那块」时，
  agent 读到的就是它。
- **`summary`** 作为 JSON 一起带过去，原样交给模型，不做解释。
- **`image`** 可以直接传 `<canvas>` 元素，也可以传 `Blob`——自己画的东西用 `canvas.toBlob(...)`，
  不是自己画的就用截图库。

加载时推一次，之后每次有意义的变化再推；octo 会把连续的推送合并成一次中继，所以画布每一笔都推也没问题。
用 `window.octo?.` 守卫一下，页面在浏览器里单独打开时照样能跑。

Agent 这边有两个工具。`artifact_state` 列出当前会话里正在发布的页面，各自带着自己的 digest
和有没有截图——便宜到你一提这个页面它就能去看一眼。`view_artifact` 把截图作为一张真正的图片拉进对话，
这也是 agent 检查自己活儿的方式：写完页面，看一眼实际渲染成什么样，再去改看着不对的地方。

**面板标题栏上的眼睛图标**表示那里打开的制品正在发布——「agent 到底能不能看见这个」从外面看就是这个样子。
没有图标，就是没在发布。

**发布不会给页面任何东西。** 拿不到对话、拿不到接口、拿不到凭据。它是单向的：页面描述自己，
而离开页面的就只有这份描述。

## 接收 agent 递过来的东西

反方向带的是 agent 产出的一个文件——比如把生成的图放到用户正在画的画布上。注册一个处理函数来接：

```js
window.octo?.onDelivery(({ blob, name, note }) => {
  // 画进去、显示出来，或者干脆不理 —— 这是你的页面
})
```

Agent 用 `insert_into_artifact` 递。目前只收图片（PNG、JPEG、GIF、WebP），一个文件加一句备注，
别的什么都没有：没有对话内容，也没有要执行的指令。不注册处理函数的页面就永远收不到东西，
而 agent 会像了解这个页面的其他一切一样知道结果——读它接下来发布的内容。

## 够不着的部分

- **Agent 从不读 DOM。** 它看到的只有页面自己选择发布的 digest、summary 和截图，再没有别的。
- **锁死在一段对话里。** 页面只能以 Web UI 给它那个 frame 的身份发布，中继会拒掉不是这个会话写出的路径，
  工具也只读当前会话的镜像。一段对话的制品对另一段完全不可见。
- **不落盘。** 快照只在内存里：截图会被下一次推送替换，5 分钟后算 stale，30 分钟后被驱逐，
  frame 一关就没了。只有真的被 `view_artifact` 交给模型的那张截图才会进入对话。
