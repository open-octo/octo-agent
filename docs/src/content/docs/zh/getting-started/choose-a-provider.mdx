octo 原生支持两种协议——Anthropic Messages 和 OpenAI Chat Completions——所以"选哪个 provider"实际上是
在这两种协议里选一种。

<Tabs>
<TabItem label="Anthropic">

```bash
export ANTHROPIC_API_KEY=sk-ant-...
octo --provider anthropic --model claude-sonnet-5 "..."
```

</TabItem>
<TabItem label="OpenAI / 兼容端点">

```bash
export OPENAI_API_KEY=sk-...
octo --provider openai --model gpt-4o-mini "..."
```

DeepSeek、百炼，以及其他 OpenAI 兼容 API 都走同一套协议。

</TabItem>
<TabItem label="自定义端点">

自托管和第三方端点（vLLM、OpenRouter、代理）走 `custom` vendor——唯一支持自定义 base URL 的一种。
它的协议（`openai` | `anthropic`）按配置项单独选择，用 `octo config` 设置一次即可（选 **Custom** →
选协议 → 填 base URL + model）：

```bash
CUSTOM_BASE_URL=https://api.deepseek.com/anthropic \
CUSTOM_API_KEY=sk-... \
  octo --model deepseek-chat "..."
```

</TabItem>

## 本地模型（Ollama、vLLM）

本地推理服务都提供 OpenAI 兼容接口，所以按 `custom` 端点配置，`protocol: openai`。有两个地方容易踩坑：

- **`base_url` 填 OpenAI 兼容接口的根路径，不是服务自己的原生 API。** Ollama 是
  `http://localhost:11434/v1`，不是 `/api`（那是 Ollama 自己的 API）。octo 对以 `/v1` 结尾的 URL
  追加 `/chat/completions`，否则追加完整的 `/v1/chat/completions`，所以填 `http://localhost:11434/api`
  会变成 `…/api/v1/chat/completions`，Ollama 直接返回 404。vLLM 默认是 `http://localhost:8000/v1`。
- **不需要 API key。** `api_key` 不写或留空即可，octo 不会发 `Authorization` 头。只有 `custom`
  vendor 允许无 key；`openai` 这类命名厂商仍然强制要 key，所以本地服务请配成 `custom`。

```yaml
endpoints:
  - id: ollama
    provider: custom
    protocol: openai
    base_url: http://localhost:11434/v1
    models:
      - model: qwen3-coder:30b
        vision: false            # 纯文本模型，别把图片发给它
default: ollama::qwen3-coder:30b
```

不改配置文件、只用环境变量也可以：

```bash
CUSTOM_BASE_URL=http://localhost:11434/v1 \
  octo --model qwen3-coder:30b "..."
```

## 存成默认值

```bash
octo config        # 交互式向导
octo config show   # 打印生效的设置及其来源
octo config path   # 打印配置文件路径
```

`octo config` 会把你的默认 provider、model、（可选的）base URL 和推理设置写进 `~/.octo/config.yml`，
这样裸跑 `octo` 就不用每次重敲 `--provider`/`--model` 了。

<Aside type="note" title="优先级">
**命令行 flag > 环境变量 > `~/.octo/config.yml` > 内置默认**。API key 优先从
`ANTHROPIC_API_KEY` / `OPENAI_API_KEY` 读取；向导可以把 key 存进文件（权限 `0600`），但更推荐用环境变量。
</Aside>

## 通过代理访问

访问 OpenAI、Anthropic 等境外端点需要代理时，octo 沿用 Go 的标准代理环境变量——`HTTPS_PROXY`、`HTTP_PROXY`、`NO_PROXY`（支持 `http://` 和 `socks5://` 地址，大小写写法都认）：

```bash
HTTPS_PROXY=http://127.0.0.1:7890 octo --provider openai "..."
```

从终端启动时在 shell 里 export 就够了。但**桌面应用和后台运行的 `octo serve` 不会继承 shell 环境**——在 `~/.zshrc` 里 export 对它们无效。统一的办法是写进 `~/.octo/serve.env`，所有启动方式（CLI、桌面版、`octo serve`）都会在启动时加载它：

```bash
cat >> ~/.octo/serve.env << 'EOF'
HTTPS_PROXY=http://127.0.0.1:7890
EOF
chmod 600 ~/.octo/serve.env
```

改完重启应用生效。代理对进程的所有出网流量生效（模型 API、搜索、更新检查等）；如果只想让部分域名走代理，请在代理软件（Clash 等）的分流规则里配置，或用 `NO_PROXY=api.moonshot.cn` 逐个排除——octo 不提供按 provider 分开的代理设置。

## 扩展推理

推理模型可以在回答前先思考。两个开关控制这个行为，同时支持 CLI flag 和 `octo config` 默认值：

- `--reasoning-effort low|medium|high|xhigh|max` —— 推理强度。OpenAI 协议后端会原样收到
  `reasoning_effort`；Anthropic 协议后端会按模型family映射成自适应思考或扩展思考的 token 预算。
  留空（默认）表示关闭。
- `--show-reasoning`（默认**关闭**）—— 把推理/思考轨迹提供给 **Web UI** 显示。终端始终不渲染思考轨迹。

这套机制把 Anthropic 的 `thinking` block 和 OpenAI 的 `reasoning_content` 统一到了同一对开关背后。
