octo 是一个跑在本机的服务，前面挂着一个 Web 界面。你只需要启动一次服务，然后在浏览器里打开它——接模型、
做个性化设置、真正干活，全都在这个页面上完成。你的对话和文件都留在本机；出网的只有发往你选定的模型服务商的请求、更新徽标背后的版本检查，以及你让它去抓的网页。

整个过程大约五分钟，其中大部分时间是在和助手聊天。

## 1 · 启动服务

<Tabs syncKey="entry">
<TabItem label="命令行">

```bash
octo serve -d
```

`-d` 表示后台运行。它监听 `127.0.0.1:8088`，并打印出可以直接打开的地址：

```
octo serve daemon started (pid 51234), ready at http://127.0.0.1:8088
```

不加 `-d` 就是前台运行，日志直接打在终端里。

另外两条迟早会用到：

```bash
octo serve --status   # 看它有没有在跑、跑在哪
octo serve --stop     # 停掉
```

</TabItem>
<TabItem label="桌面版">

桌面 App **本身就是那个服务**——它在 `127.0.0.1:8088` 上启动同一套东西，套一个原生窗口，关掉窗口之后
继续留在托盘/菜单栏里跑着。你的编辑器、浏览器、手机连的都是这一个实例。

直接启动它，然后跳到第 3 步；窗口里就是本文说的那套界面。

</TabItem>
</Tabs>

## 2 · 打开控制台

浏览器访问 **http://127.0.0.1:8088**。

<Aside type="tip" title="本机访问不需要密钥">
`127.0.0.1` 是回环地址，octo 默认信任它。只有当你把服务绑到更大的范围（`-addr :8088`）让别的机器也能访问时，
才会用到 access key——见[自托管](/docs/zh/guides/self-host/)。
</Aside>

## 3 · 首次配置

全新安装打开后会看到一个配置面板——**欢迎使用 Octo**——在模型接好之前，它会挡住其余界面。没有模型，
助手什么也做不了，所以这一段是表单而不是聊天。

<Steps>

1. **语言**。English 或简体中文。这同时决定界面语言和助手跟你说话用的语言。点**继续 →**。

2. **连接模型**。从**服务商**下拉里挑一个——OpenAI、Anthropic、OpenRouter、xAI、DeepSeek、Minimax、
   Kimi、Kimi Coding Plan、GLM、Bailian (Alibaba)、MiMo、LongCat——其他的选 **Custom**。选预设会自动带上它自己的
   Base URL 和协议，你只需要填**模型**和 **API Key**。

   选 **Custom** 会多出一个**协议**选择（OpenAI Chat Completions 或 Anthropic Messages），**Base URL**
   也可以随便填。如果接的是 Ollama、vLLM 这类本地服务，API Key 留空就行——输入框里也这么写着。

   **测试并继续 →** 会在保存前真发一次请求，所以密钥填错、地址不通这类问题会当场暴露，而不是等到你
   发第一条消息。

3. **浏览器自动化（可选）**。octo 可以操作你已登录的真实浏览器——点击、输入、回放工作流。这需要在那个
   浏览器里打开远程调试，面板上有具体步骤。点**以后再说**也完全没问题，设置里随时可以再配。

</Steps>

## 4 · 认识你的助手

配置走完，你会直接落在一个叫 **✨ 新手引导**的会话里，里面已经替你发了一条消息 —— `/onboard lang:zh`，带着你刚选的语言。
这是一场真正的对话，不是表单——用你自己的话回答就行，之后什么都能改。

它会依次问：

- **想叫它什么**。会给几个候选名字，你也可以随便输。留空就还叫 Octo。
- **想要什么性格**——专业型、友好型、创意型、简洁型。这几个会以可点击的卡片形式出现。
- **你是谁**。名字、职业、最想拿它来做什么，以及你的链接（GitHub、个人网站之类）。全都可选。
  给了链接，它会去读那些公开页面来了解你。
- **三项偏好**。权限模式（敏感操作前问你，还是自动放行）、推理强度、以及要不要显示推理过程。

问完它会写下两个文件，另外把那三项偏好存进 `config.yml`：

| 文件 | 内容 |
|---|---|
| `~/.octo/soul.md` | 助手是谁——名字、性格、做事方式 |
| `~/.octo/user.md` | 你是谁——它带进每一次会话的那份档案 |
| `~/.octo/config.yml` | 权限模式、推理强度、是否显示推理过程——对每个会话都生效 |

两个都是普通 Markdown，你随时可以手改。以后想重做其中任何一部分，直接开口就行——「改一下你的性格」、
「更新一下我的资料」——同样的流程会只针对那一块再走一遍。

<Aside>
引导中途退出没关系，它不会每次重启都来烦你。它写下的东西都在
**设置 → 数据管理 → 助手记忆 → 管理**里，那里把**灵魂**、**用户**、**记忆**并排放着，
每一块都有一个**让助手更新此内容**按钮。
</Aside>

## 5 · 你的第一个真任务

底部的输入框就是一切的入口。Enter 发送，Shift+Enter 换行，输入 `/` 会弹出技能列表。

找一件需要动手而不只是动嘴的事交给它：

```text
看一下 ~/Downloads 里的文件，告诉我哪些最占地方，
再把一年以前的都挪进一个 Archive 文件夹。
```

工具——shell、读写改文件、搜索、抓网页——默认全部开启，所以它是真的会去做。每一步碰了什么都会以
工具卡片的形式显示在对话里；如果你的权限模式是交互式，敏感操作之前它会先问你。

这个界面上还有几处值得先知道：

- **左侧栏**——**新建会话**开一个新的；下面的列表是已保存的会话；**定时任务**和**轻应用**在指南里有专门
  介绍；**更多**里收着专家、技能、MCP 服务器、工作流、浏览器、渠道；**设置**在最底下。
- **输入框下面那条**——模型选择器、推理开关、显示上下文占用的**上下文**百分比，以及权限模式。
- **会话顶栏**——**压缩**把长对话摘要掉腾出上下文，**导出**把记录转成 MD、JSON、PDF、PNG、HTML：勾选要导出的消息，决定要不要带上工具调用，再点一个格式。

## 东西都放在哪

octo 的所有数据都在 `~/.octo/` 下（Windows 是 `%USERPROFILE%\.octo\`）：`config.yml` 存端点和偏好，
`sessions/` 存对话记录，`soul.md` 和 `user.md` 是身份，`skills/` 放你自己加的技能。都是普通文件，
你可以随便看、改、纳入版本管理，或者删掉。

## 更喜欢用终端？

同一个助手也能以 headless 方式跑。上面的步骤已经配好了 provider，所以不需要额外设置：

```bash
octo "给 octo config show 加一个 --json 参数并跑测试"

echo "总结一下上一次提交改了什么" | octo   # 从管道读
octo --prompt-file ./task.md                # 或者从文件读
```

不带消息直接运行 `octo` 会进入终端交互界面，`octo sessions` 列出已保存的会话，`octo -c` 恢复其中一个。
`octo config` 则可以完全不碰浏览器，在终端里走完 provider 配置。
